# Zotero 插件失败修复、验证技能维护与合并

## 目标

在一次收到测试失败或要求完成插件验证的任务后，复现失败、修复根因、反复验证直到通过，再维护 `.cursor/skills/verify-zotero-codex/` 的验证流程，创建并合并一个 PR。常规目标是在用户给定期限前完成；本次期限为 **2026-10-15 07:00（Asia/Shanghai）**。

## 触发

用户要求在 Zotero Codex 仓库完成测试、修复或继续一个未完成的测试修复循环时手动触发。每次触发都先检查当前分支、工作区改动和上一轮证据；不得覆盖用户已有改动。

## 固定边界

- 从干净的 `main` 创建 `codex/` 前缀工作分支；发现工作区已有改动时保留它们，并在安全隔离后继续。
- 测试与原生验证使用合成身份、合成论文资料和独立 Zotero profile。不得把个人库数据复制到夹具，也不得把原始截图、scratch、凭据或本机绝对路径放进 Git、PR 或共享报告。
- 修复产品行为时先定位根因，只改完成修复所需的代码，并新增或更新对应回归测试。不得为了让测试变绿而删除有效断言或掩盖失败。
- 每轮都保存本地验证证据，并记录命令、原生入口、结果、失败和未覆盖路径。
- 外部前置条件缺失（例如登录态、系统锁屏、远端服务或 CI）导致必需路径不可达时，标为阻塞，保留已完成工作和证据，等待条件满足后继续。不得把跳过路径报告为通过。
- 同一失败连续 3 轮没有新证据或有效进展时暂停，简要报告阻塞点并等用户决定。出现新证据或根因修复后可继续。
- 用户已授权在所有门槛通过后自动提交、创建 PR 并合并；只在所有必需 CI 检查通过后合并。远端检查未通过或无法完成时不绕过保护规则。

## 执行顺序

1. **建立基线。** 检查仓库说明、分支和改动；读取项目验证技能及受影响功能配方。运行 `npm test`、`npm run check`、`npm run build`，并在独立 Zotero profile 中复现先前记录的原生失败。每个新 profile 启动后先运行 doctor；意外失败后重新 health-check 或重启到已知状态。
2. **复现并修复。** 按用户可见入口重现失败，保存操作、状态与截图；读代码追到根因；添加或修复覆盖该行为的回归测试。一次只处理可验证的失败单元。
3. **重复验证。** 每次代码修复后重新运行相关自动化测试，最终完整运行 `npm test`、`npm run check`、`npm run build` 和受影响的原生路径。每轮检查用户可见结果和持久状态；失败则回到根因修复。全部必需门槛通过后才进入下一步。
4. **维护验证技能。** 执行 `maintain-verification-skill`：检查特征索引；按每个 feature 文件审阅源码；在一个隔离原生会话中覆盖每个 feature；只在验证技能自己的目录修正文档、地图或 harness。其运行期间不改产品代码。无法覆盖的 feature 只有在记录了具体前置条件和尝试入口后才能标为 `verified-unreachable`；由于本流程要求必需原生路径通过，未覆盖的必需路径会使交付阻塞。
5. **准备一个 PR。** 汇总产品修复、回归测试和维护阶段确认的验证技能修正到同一 PR。重读全部改动，检查 `git diff --check`，构建准确的 PR Verification 部分：列出每条检查、原生入口和结果，链接审阅者可访问的已净化证据，并明确所有失败、限制和未测路径。不得加入私有原始证据。
6. **合并并报告。** 创建 PR，等待必需 CI/保护检查通过，再合并。若 PR 创建、检查或合并受阻，保留分支和证据并报告准确状态；不声称已完成。

## 完成条件

- 自动化基线全部通过：`npm test`、`npm run check`、`npm run build`。
- 改动影响的原生 Zotero 路径已在隔离 profile 中通过，且动作、结果状态和截图均已检查。
- `maintain-verification-skill` 完成了全 feature 源码和原生覆盖，结论为 `clean` 或 `changed`；无必需路径遗留为阻塞。
- 一个 PR 的验证说明完整，必需远端检查通过，PR 已合并。

## 用户简报

最终用简短中文报告修复内容、测试命令和原生入口、维护验证技能的结论、PR 与合并状态、证据链接，以及仍存在的限制。报告不包含真实论文信息、凭据或个人路径。
