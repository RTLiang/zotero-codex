# Paper context

The composer can attach the current paper's metadata and PDF passages. Each paper remembers its chat, and switching papers restores the appropriate context and draft.

## Sub-features

- `item-context` attaches available title, creators, date, DOI and local PDF path to the context sent to the model. It includes the URL when there is no PDF and the abstract when there is no PDF evidence. The visible attachment chip shows the title and PDF/Item type.
- `pdf-question-evidence` reads the attached local PDF through Zotero's PDFWorker before sending an item-scoped question. It selects matching passages and section headings with physical PDF page markers, keeping the context short enough to avoid Codex's middle truncation. The abstract is omitted when PDF evidence or extraction guidance is attached. This supplies paper locations without Computer Use access to the Zotero window. Extraction failure retains item metadata and the local PDF path and supplies local-PDF/OCR guidance.
- `scanned-pdf-fallback` detects empty or extremely sparse Zotero full-text extraction and tells Codex to try only locally available PDF/OCR tools on the local attachment, never a third-party OCR service. OCR claims must be labeled and page locations verified. If local OCR is unavailable, the user can add a searchable text layer locally and rebuild Zotero's full-text index before retrying.
- `current-pdf-page` captures the reader's physical page and printed label at send time, including the last active view in a split reader. With current-item context enabled, it puts that page's text before question-matched passages. Long pages carry an explicitly marked opening excerpt; missing text still preserves the page marker. Library sends and disabled item context do not attach a reading position.
- `context-toggle` includes or removes current-item metadata.
- `selection-live` uses the latest reader text selection for the next message.
- `selection-pin` pins several passages through Add to Codex and supports removing a passage.
- `paper-switch` keeps drafts, attachments and chat bindings associated with the selected paper.
- `pdf-reference` opens a cited page or jumps to a figure, table, equation or numbered section in the attached PDF. A tagged figure/table with a labeled bounding box uses the PDF structure tree; sections use the PDF outline when present; other references use PDF text positions. Plain-text page, section, figure, table and equation mentions and quotations stay text; only explicit Markdown citations navigate, because a mention alone does not identify its source document. Navigation crosses into the reader through `Zotero.Reader.navigate`.
- `same-paper-links` opens links to this paper's arXiv, DOI or catalog URL in its attached PDF. Page, section and method locators position the reader. Current-paper title labels such as `paper` or `全文` render as page-one PDF references; ordinary HTTP labels retain their URL, but clicking still checks for a saved local paper. Unmatched links open their original URL.
- `other-local-paper-links` checks linked web papers against Zotero's local item URLs, DOIs and arXiv identifiers when clicked. A matching item with a PDF uses the same explicit page, numbered-section, figure, table, equation and original-passage locators as the current paper; legacy section labels and method labels are also supported, including when the current item has no PDF. A combined page hint and section label must show the section heading. A matching item without a PDF is selected in the library. Unmatched links open their original web URL.
- `citation-harness` supplies a trusted citation contract on new, resumed and forked chats, without repeating it in turn context. Codex should emit current-PDF Markdown targets `#page=N`, `#section=N`, `#figure=N`, `#table=N` and `#equation=N`, verified against the attached PDF or original excerpts. Excerpts distinguish physical PDF pages from printed page labels. Visible citation labels follow the answer language independently of plugin UI language; the explicit target controls navigation independently of its visible label. Current-PDF fragments belong only to the current turn's item; other-paper citations carry that source's own verified absolute URL and source name on every link. The contract audits source identity together with the locator and keeps uncertain mentions as plain text.
- `quote-highlight` uses `#page=N&quote=URI-encoded-original-text` to locate a verbatim passage on its physical PDF page and briefly highlight the reader's exact character rectangles. It closes Find without adding a library annotation. Missing or repeated passages report an error instead of choosing another occurrence.

## How to get to it (user POV)

- Select a paper in My Library, then click Codex in the right sidenav.
- Open a PDF and click Codex in the reader's right sidenav.
- Browse to a page and ask "Explain this page" with Include current item enabled. The next message uses that reading position without requiring a text selection.
- Click the composer's Item button or +, then Include current item. The current-paper attachment also has a remove button.
- Select PDF text to attach the live selection. Click Add to Codex in the selection popup to pin it.
- Click a page, figure, table, equation or section reference in an assistant reply to return to its PDF location. Bare locators and paraphrases remain plain text.
- Click a link to the current paper in an existing assistant reply; it should open the Zotero PDF rather than an online copy.
- Click a link to another paper already saved in Zotero; its local PDF or library item should open.

## Driving it with control.mjs and native app control

Preconditions:

- Doctor passes. Run `seed` once or use the fixtures already created by `prove`.
- Metadata-only checks need no model reply. Reader paths require a disposable local PDF attached to a fixture paper. Importing it with the helper prepares fixture data; it does not verify Zotero's manual attachment UI.
- `seed` and `prove` accept `--entry reader --pdf /absolute/path/to/fixture.pdf` to import a chosen local PDF as fixture data into the isolated profile. Without `--pdf`, they generate the one-page permission fixture. The original file is read without modification.

- Select paper A by its visible title in `#zotero-items-tree [role="treeitem"]`. `snapshot paper-list --run "$verify_run"` exposes the current row ID. In the fresh fixture list A is `#item-tree-main-default-row-0`; use `click '#item-tree-main-default-row-0'` with the run argument and confirm the title before relying on the index.
- Click the visible Codex `[data-pane]` button whose value contains `codex-sidebar`. The smoke resolves this handle dynamically. Capture `snapshot paper-context-before --run "$verify_run"`; expect Verification paper A in the attachment.
- Open with `click '.zcs-context-mode'` or `click '.zcs-add-button'`, then toggle with `click '.zcs-context-option'`. Expect the paper chip in `.zcs-attachments` to disappear and reappear. Repeat both menu entry points for a full toggle claim.
- Type an unsent draft with `fill '.zcs-input' 'Draft for paper A'`. Select B's title-bearing row with pointer actions. If Zotero shows Info, reopen the visible Codex sidenav. Wait for the composer to be visible and enabled before typing or capturing after each paper change. Confirm A's draft/context does not appear on B. Return to A, reopen Codex if needed, and capture the restored draft. Test ordinary A→B→A switching separately from settings reconnection; restoration after reconnect does not establish ordinary switching. Record draft loss as a product failure. No direct view setters count as proof.
- For PDF entry, open the fixture attachment in Zotero using native app control, click its Codex sidenav, then select visible text with a real pointer drag. Capture the selection action and the `.zcs-live-selection-attachment` result. Click the selection popup's `.zcs-reader-add` button in the reader document and select another passage. Expect separate pinned `.zcs-selection-attachment` chips. The main-window helper does not traverse the embedded PDF text layer; native control must perform this step.
- Remove a live or pinned passage through that chip's `.zcs-attachment-remove`, then capture the attachment list. For an authenticated send, inspect the stored user turn as well as the screen to confirm only the intended passages were sent and consumed.
- For PDF reference links, use a real assistant reply in an authenticated scratch profile. Click a page link, a numbered section link, and a figure/table/equation link in `.zcs-assistant .zcs-pdf-reference`. Check that bare locators and paraphrases have no link, including under a heading naming another document. Explicit current-PDF fragments must still navigate. Use both a tagged PDF with labeled figure bounds and an untagged PDF with a searchable caption. Capture the reader page before and after each click; the figure or table body should be visible without the Find popup. Verify an unmatched reference reports that it could not be located without opening Find. A seeded or fabricated assistant transcript does not prove this path.
- For `same-paper-links`, use a real reply with a Markdown link to the current paper's online copy and a local PDF attachment. Click its `.zcs-pdf-reference` and confirm the current Zotero attachment opens, including the requested page when the link has `#page=N`. An unrelated external link in that PDF-scoped answer should remain an anchor with its original URL. Check the stored reply separately so the display-only routing is not mistaken for changed model output.
- For `other-local-paper-links`, save two disposable papers with invented URLs and PDFs. In a real reply about the first, request adjacent current/other-document links using `#page=5` and labels naming `section 3.2.2` or `3.2.2 节`. Click both: verify different target attachments, physical page 5, the exact heading visible, closed Find and unchanged annotations. Include a wrapped inline link to exercise the helper's client-rectangle pointer targeting. Repeat the other-document link from a metadata-only current item. Check that an unmatched link retains its original web URL, and a matching target without a PDF selects its library row. Inspect saved Markdown separately. Without an authenticated scratch reply, native search and reader API checks can establish only part of this path; report the click route as unverified.
- For `citation-harness`, ask a normal paper question in a new authenticated scratch chat, reconnect through settings, reopen the chat and send another turn, then edit an earlier message to fork it. Reopening an already cached chat alone does not establish a backend resume. Inspect each real stored response for supported Markdown targets and verified source locations. Ask for a comparison with a second synthetic document, including overlapping section and figure numbers, and inspect new, resumed and forked replies: each other-document citation must repeat its own absolute URL and source name. Include bare Chinese and English locators and confirm they remain text. Click adjacent explicit current/other-document citations and independently verify the attachment IDs; an unavailable other source must retain its URL or plain text rather than navigate the current PDF. Click a generated section link and confirm the native PDF reaches that heading. A model transport probe establishes generated output only; it does not prove the native click path.
- For `pdf-question-evidence`, import a multipage PDF into the isolated reader profile and send a question about a heading near the end. Inspect the stored user turn's `additionalContext.zotero.value` for the matching text and its physical page marker, then inspect the answer and approval area. Confirm the answer can locate the heading without a Computer Use permission request. Repeat with a Chinese question about an English heading. The PDFWorker call and context formatting can be checked read-only in the isolated profile without login; the actual send and absence of an approval card require an authenticated scratch profile.
- For `scanned-pdf-fallback`, use a synthetic image-only PDF with invented text. Confirm Zotero's PDFWorker returns empty/sparse text and that the generated context includes the local-OCR guidance instead of claiming the document has no relevant content. Unit tests cover this fallback without login; a real OCR answer requires an authenticated scratch profile with a local OCR-capable tool. Never use a real paper as the fixture.
- For `current-pdf-page`, use a synthetic multipage PDF with distinct printed labels and text on each page. Navigate through the reader toolbar, send "Explain this page" without selecting text, and inspect the stored turn for the physical page, printed label, and that page's text before other excerpts. Turn the page and repeat to exclude stale context. Repeat in a split reader's second view, and confirm library sends and disabled item context omit the reading position. Without authentication, read `currentPdfPage` and `pdfEvidenceForQuestion` against the live fixture reader to verify acquisition and extraction; report the actual send and model interpretation as unverified.
- For `quote-highlight`, provide a verified original excerpt and physical page, ask for a verbatim citation, and inspect the real response's encoded quote target. Focus the isolated window, then click its anchor with `click SELECTOR --capture quote-highlight --capture-when SCRIPT_FILE --run "$verify_run"`. The read-only condition should observe the current reader's `_internalReader._primaryView._highlightedPosition`, so the screenshot catches the temporary highlight before it expires. Zotero clears that state about two seconds after navigation (`_highlightPosition` in the reader bundle's `resource/reader/reader.js`) and clears it at once on the next pointer-down inside the page, so the capture has to land inside that window and must not click the page first. Confirm the intended words across line breaks are highlighted on the cited page, Find stays closed and the attachment's annotation count is unchanged. Expect only Zotero's transient position highlight after navigation. The plugin clears Find in `finally` before navigating to the matched character rectangles, including when lookup fails. Independently verify that `_primaryView._findController._highlightMatches` is false and that Find is inactive with an empty query and closed popup; watching only `_highlightedPosition` would miss a Find-cleanup regression. Clicking the page clears the transient position highlight; it never becomes a library annotation. Check missing and repeated text separately. The display label can be translated, but the target must contain original PDF wording.

## Gotchas

- Item rows use `role="treeitem"`, not `role="row"`. Their numeric suffix is a rendered index, not the Zotero database ID.
- After each search-based figure/table/equation or quote jump, repeat the click with `--capture reference-settled --capture-when .cursor/skills/verify-zotero-codex/scripts/pdf-reference-settled.js`. Inspect the settled screenshot and compare annotations to the baseline. The condition requires no position highlight, inactive Find, an empty query, a closed popup and no highlighted matches. Repeat failures and valid recovery; checking only the short-lived position highlight misses persistent Find paint.
- A paper without a PDF is valid for metadata checks but cannot prove reader selection behavior.
- The main window can retain both library and reader panes. Scope DOM selectors to the visible pane and use native control only on the owned fixture window.
- Replacing live selection and pinning selection are different operations. Cover both when selection handling changes.
- Figure and table numbers can also occur in surrounding prose. In tagged PDFs, check that the structure label and box refer to the actual object. In untagged PDFs, check that a caption anchors the jump and the figure or table body is visible; report cases where the PDF text has no usable caption.
- For a section bookmark with XYZ coordinates, check that the heading itself is visible after navigation, including headings near a page's bottom. A valid destination or a changed page number alone does not establish this. Physical-page citations use the page index and must not be redirected by printed page labels.
- Existing replies keep their original stored Markdown. The sidebar changes their clickable destination when it renders them; copying the raw reply can still include the old online URL.
- Unsent draft restoration is distinct from persisted conversation bindings. A chat-binding claim needs a real created chat for each paper and reopening evidence.
